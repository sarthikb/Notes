## 📘 What is Consistent Hashing?

**Consistent Hashing** is a strategy used in **distributed systems** to **distribute data across nodes (servers)** **efficiently** and with **minimal rebalancing** when nodes join or leave the system.

---

## 🔥 Problem It Solves

In traditional hashing (like `hash(key) % N`), **adding/removing a server changes all mappings**:

* Example: You have 3 servers.

  ```
  Server = hash(key) % 3
  ```

  Now you add a 4th server. All keys get new hashes → 🔥 **Rebalancing required for almost all keys**.

### ❌ Bad For:

* Distributed caching (e.g., Memcached)
* Sharding in databases
* Scalable load balancing

---

## ✅ Consistent Hashing to the Rescue

Instead of using `hash(key) % N`, we map **both servers and keys** to a **ring (circular hash space)**.

---

### 📈 How It Works:

1. **Create a circular hash space** (e.g., 0 to 2³² - 1).
2. **Hash each server** and place them on this ring.
3. **Hash each key**, and assign it to the **first server clockwise** from its hash.

---

### 🧩 Example

#### Servers: A, B, C

Let's say the hash ring looks like:

```
   0
   |
   |
 C |----- A
   |     /
   |    /
   |   /
   ---- B (clockwise)
```

* Hash("A") → position 60
* Hash("B") → position 120
* Hash("C") → position 250

**Keys**:

* hash("apple") = 100 → Goes to **B**
* hash("zebra") = 240 → Goes to **C**
* hash("dog") = 10 → Goes to **A**

---

### 💡 If Server B is Removed:

Only keys between A and C are rehashed — not all keys.
Minimal disruption = ✅

---

## 🔃 Virtual Nodes (VNodes)

To prevent **uneven data distribution**, each physical server is assigned **multiple positions** on the ring.

* E.g., Server A could be at positions 10, 130, 250
* So keys are more evenly spread even with few nodes

### 🧩 Example with Virtual Nodes

| Server | Virtual Node Hashes |
| ------ | ------------------- |
| A      | 10, 130, 250        |
| B      | 30, 180, 300        |

Each key will be mapped to the next clockwise vnode — giving better load balancing.

---

## 🔄 Summary of Flow

1. Hash servers (multiple times if using VNodes).
2. Hash key → find the closest server clockwise.
3. When server leaves/joins, **only nearby keys move**.

---

## 📊 Time & Space Complexity

| Operation   | Time     |
| ----------- | -------- |
| Add Node    | O(log N) |
| Remove Node | O(log N) |
| Lookup Key  | O(log N) |

With TreeMap or a Sorted Map (like Java's `TreeMap`), you can implement this easily.

## 💻 Java Code for Consistent Hashing

```java
import java.util.*;

public class ConsistentHashing {
    private final SortedMap<Integer, String> ring = new TreeMap<>();
    private final int VIRTUAL_NODES = 3;

    private int hash(String key) {
        return key.hashCode() & 0x7fffffff; // positive int
    }

    public void addServer(String server) {
        for (int i = 0; i < VIRTUAL_NODES; i++) {
            int h = hash(server + "#" + i);
            ring.put(h, server);
            System.out.println("Added virtual node " + server + "#" + i + " with hash " + h);
        }
    }

    public void removeServer(String server) {
        for (int i = 0; i < VIRTUAL_NODES; i++) {
            int h = hash(server + "#" + i);
            ring.remove(h);
            System.out.println("Removed virtual node " + server + "#" + i + " with hash " + h);
        }
    }

    public String getServer(String key) {
        if (ring.isEmpty()) return null;

        int h = hash(key);
        SortedMap<Integer, String> tail = ring.tailMap(h);
        int nodeHash = tail.isEmpty() ? ring.firstKey() : tail.firstKey();

        return ring.get(nodeHash);
    }

    public static void main(String[] args) {
        ConsistentHashing ch = new ConsistentHashing();

        ch.addServer("A");
        ch.addServer("B");
        ch.addServer("C");

        String[] keys = {"apple", "banana", "cat", "dog", "elephant"};
        for (String key : keys) {
            System.out.println("Key " + key + " is mapped to server " + ch.getServer(key));
        }

        System.out.println("\nRemoving server B...\n");
        ch.removeServer("B");

        for (String key : keys) {
            System.out.println("Key " + key + " is mapped to server " + ch.getServer(key));
        }
    }
}
```

## Understanding Consistent Hashing

### The Core Idea

Consistent hashing is a hashing scheme that minimizes reassigning keys when nodes join or leave in a distributed system.

* Unlike traditional modulo-based hashing (`hash(key) % N`), which redistributes *all* keys when `N` changes, consistent hashing only affects a small proportion. ([Wikipedia][1], [Coduva][2])

### How It Works (Simplified)

1. **Hash the servers** to assign each a position on a circular hash ring.
2. **Hash each key**; locate it on the ring.
3. **Traverse clockwise** from the key's position to find the first server—you assign the key to that server. ([Wikipedia][1], [Grokking The System Design][3])

### Impact of Node Changes

* **Adding a node** → Only keys between its position and the next predecessor change assignment.
* **Removing a node** → Only the keys it was responsible for are reassigned to the next node. ([Coduva][2], [LinkedIn][4])

### Benefits

* **Scalability**: Easy to add or remove servers without massive rebalancing. ([Coduva][2], [Wikipedia][1])
* **Fault tolerance**: System remains stable when nodes fail.
* **Even distribution with minimal disruption**.

---

## Virtual Nodes (VNodes) — Enhancing Balance

A key challenge: With few servers, some may cluster and receive disproportionate keys.

**Solution**: Assign multiple "virtual nodes" per server—each is a distinct point on the ring.

* This smooths out key distribution.
* On adding/removing a physical server, only its virtual nodes and the keys they handle are affected. ([Wikipedia][1], [Medium][5], [Medium][6])
* Popular systems like Cassandra, DynamoDB, and CDNs use this pattern.

---

## Real-World Example Walkthrough

### Imagine:

* **Servers**: A, B, C
* **Hash ring** positions (signed for illustration):

```
0 — A — 30 — B — 60 — C — (back to 0)
```

* **Key hashes**:

  * "apple" → 50 (maps to C)
  * "banana" → 10 (maps to A)

#### If we add **Server D** at position 40:

* Only "apple" (50) gets re-mapped—from C to D.
* "banana" remains with A. ([LinkedIn][4], [Coduva][2])

## Java Implementation (Efficient with TreeMap)

```java
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;
import java.util.SortedMap;
import java.util.TreeMap;

public class ConsistentHashing {
    private final TreeMap<Long, String> ring = new TreeMap<>();
    private final int numberOfReplicas;
    private final MessageDigest md;

    public ConsistentHashing(int numberOfReplicas) throws NoSuchAlgorithmException {
        this.numberOfReplicas = numberOfReplicas;
        this.md = MessageDigest.getInstance("MD5");
    }

    private long generateHash(String key) {
        md.reset();
        md.update(key.getBytes());
        byte[] digest = md.digest();
        long hash = ((digest[3] & 0xFFL) << 24) | ((digest[2] & 0xFFL) << 16)
                    | ((digest[1] & 0xFFL) << 8) | (digest[0] & 0xFFL);
        return hash;
    }

    public void addServer(String server) {
        for (int i = 0; i < numberOfReplicas; i++) {
            long hash = generateHash(server + "-" + i);
            ring.put(hash, server);
        }
    }

    public void removeServer(String server) {
        for (int i = 0; i < numberOfReplicas; i++) {
            ring.remove(generateHash(server + "-" + i));
        }
    }

    public String getServer(String key) {
        if (ring.isEmpty()) return null;
        long hash = generateHash(key);
        SortedMap<Long, String> tail = ring.tailMap(hash);
        long target = tail.isEmpty() ? ring.firstKey() : tail.firstKey();
        return ring.get(target);
    }

    public static void main(String[] args) throws NoSuchAlgorithmException {
        ConsistentHashing ch = new ConsistentHashing(3);
        ch.addServer("A"); ch.addServer("B"); ch.addServer("C");

        for (String key : new String[]{"apple", "banana", "cherry"}) {
            System.out.println(key + " → " + ch.getServer(key));
        }

        System.out.println("Removing B...");
        ch.removeServer("B");

        for (String key : new String[]{"apple", "banana", "cherry"}) {
            System.out.println(key + " → " + ch.getServer(key));
        }
    }
}
```

This implementation uses `TreeMap` to simulate the ring and MD5 hashing for keys and virtual nodes. ([Medium][6], [techshshila.in][7])
