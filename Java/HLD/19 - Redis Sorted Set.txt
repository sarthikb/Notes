Redis **Sorted Sets (ZSETs)** are one of the *best* data structures for **rate limiting**, especially sliding-window rate limiting.
Their ordering by numeric score makes them perfect for storing timestamps and trimming old requests efficiently.

Below is a clear guide on how ZSET-based rate limiting works.

---

# ⭐ Why Sorted Sets for Rate Limiting?

* **Score = timestamp** (e.g., milliseconds)
* **Member = unique ID for each request** (request ID or timestamp+random)
* Allows:

  * Fast removal of old entries (`ZREMRANGEBYSCORE`)
  * Fast counting of recent requests (`ZCOUNT`)
  * Enforcement of a **sliding time window**

Runtime: **O(log N)** per request

---

# 🚦 Sliding Window Rate Limiter (Common Pattern)

### Allow **N requests per window T** (e.g., 100 requests per 60 seconds)

## Algorithm using ZSET

Let:

* Key: `rate:user:{user_id}`
* Window: `T = 60 sec`
* Limit: `N = 100`
* Current timestamp: `now`

### Steps per request:

#### **1. Remove old entries (older than now - T)**

```redis
ZREMRANGEBYSCORE rate:user:42 0 (now - T)
```

#### **2. Add the current request**

```redis
ZADD rate:user:42 now now
```

#### **3. Count requests in the window**

```redis
ZCOUNT rate:user:42 (now - T) now
```

#### **4. Check limit**

If count > 100 → **rate limit exceeded**
Else → **allow**

---

# 🔁 Atomic Version (Using MULTI/EXEC)

To avoid race conditions:

```redis
MULTI
  ZREMRANGEBYSCORE rate:user:42 0 (now - T)
  ZADD rate:user:42 now now
  ZCOUNT rate:user:42 (now - T) now
EXEC
```

---

# ⚡ Even Better: Use a Lua Script (Single round-trip)

```redis
-- KEYS[1] = key
-- ARGV[1] = now
-- ARGV[2] = window
-- ARGV[3] = limit

local key = KEYS[1]
local now = tonumber(ARGV[1])
local window = tonumber(ARGV[2])
local limit = tonumber(ARGV[3])

redis.call("ZREMRANGEBYSCORE", key, 0, now - window)
redis.call("ZADD", key, now, now)
local count = redis.call("ZCOUNT", key, now - window, now)

if count > limit then
  return 0 -- blocked
else
  return 1 -- allowed
end
```

---

# 🧮 Memory Considerations

To avoid unbounded growth, add an expiration:

```redis
EXPIRE rate:user:42 120  # double the window as a safe margin
```

---

# 🔄 Variations of Rate Limiting Using Sorted Sets

### 1. **Fixed Window** (less accurate)

Use a single counter per window — not ZSET-based.

### 2. **Sliding Log** (**uses ZSET**) ✔

Most accurate; recommended for high-value APIs.

### 3. **Token Bucket / Leaky Bucket**

More complex, often uses small Lua scripts, and ZSETs only optionally.

---

# 📘 Example in Python

```python
import time
import redis

r = redis.Redis()

def allow_request(user):
    now = int(time.time() * 1000)
    key = f"rate:user:{user}"
    window = 60000
    limit = 100

    pipe = r.pipeline()
    pipe.zremrangebyscore(key, 0, now - window)
    pipe.zadd(key, {now: now})
    pipe.zcount(key, now - window, now)
    result = pipe.execute()

    return result[-1] <= limit

print(allow_request("42"))
```
