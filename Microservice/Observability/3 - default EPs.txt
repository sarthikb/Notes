By default, when you add **Spring Boot Actuator** + **Micrometer Prometheus registry**, the
`/actuator/prometheus` endpoint exposes a **rich set of automatically collected metrics**.

Below is a **clear, structured breakdown** of what you get **out of the box**, with examples and what they mean in real systems.

---

## High-Level Categories of Default Metrics

Spring Boot uses **Micrometer** as a facade, so the metrics come from:

* JVM
* HTTP server
* Spring MVC / WebFlux
* System & process
* Logging
* Tomcat / Netty (depending on server)
* Datasource (if present)

---

## 1️⃣ JVM Metrics (Always Present)

### Memory

```
jvm_memory_used_bytes
jvm_memory_max_bytes
```

Tags:

* `area=heap|nonheap`
* `id=G1 Eden Space`, `Metaspace`

👉 Used to detect:

* Memory leaks
* Heap pressure
* OOM risks

---

### Garbage Collection

```
jvm_gc_pause_seconds_count
jvm_gc_pause_seconds_sum
```

👉 Used to detect:

* Long GC pauses
* Excessive GC activity

---

### Threads

```
jvm_threads_live_threads
jvm_threads_daemon_threads
```

👉 Used to detect:

* Thread leaks
* Saturation under load

---

## 2️⃣ CPU & Process Metrics

### CPU

```
process_cpu_usage
system_cpu_usage
```

👉 Used for:

* HPA scaling decisions
* Performance bottlenecks

---

### Uptime

```
process_uptime_seconds
process_start_time_seconds
```

---

## 3️⃣ HTTP Server Metrics (Very Important)

### Request Count & Latency

```
http_server_requests_seconds_count
http_server_requests_seconds_sum
http_server_requests_seconds_bucket
```

Tags include:

* `method=GET|POST`
* `status=200|500`
* `uri=/orders/{id}`

👉 Used for:

* Throughput (RPS)
* Latency (p95, p99)
* Error rates

---

### Example Metric Line

```
http_server_requests_seconds_bucket{method="GET",uri="/orders",status="200",le="0.5"} 145
```

---

## 4️⃣ Embedded Server Metrics

Depends on server:

### Tomcat (default)

```
tomcat_threads_busy
tomcat_threads_current
tomcat_sessions_active_current
```

👉 Used to detect:

* Thread pool exhaustion
* Connection saturation

---

### Netty (WebFlux)

```
reactor_netty_http_server_requests_seconds
```

---

## 5️⃣ Logging Metrics

```
logback_events_total{level="ERROR"}
logback_events_total{level="WARN"}
```

👉 Used for:

* Error spikes
* Log-level analysis

---

## 6️⃣ Spring Framework Metrics

### Controller Invocation

```
spring_webmvc_request_seconds
```

### Bean Initialization

```
spring_context_startup_time_seconds
```

---

## 7️⃣ Datasource / Database Metrics (If DB Configured)

If using **HikariCP** (default):

```
hikaricp_connections_active
hikaricp_connections_idle
hikaricp_connections_max
```

👉 Used to detect:

* Connection pool exhaustion
* DB performance issues

---

## 8️⃣ Cache Metrics (If Enabled)

If using caches (e.g. Caffeine, Redis):

```
cache_gets_total
cache_puts_total
cache_evictions_total
```

---

## 9️⃣ Application Info (Minimal)

```
application_ready_time_seconds
application_started_time_seconds
```

---

## What Is *NOT* Exposed by Default ❌

| Not Included         | Reason                |
| -------------------- | --------------------- |
| Business metrics     | App-specific          |
| Custom method timing | Needs annotations     |
| External API metrics | Needs instrumentation |
| Distributed traces   | Requires tracing libs |

---

## Sample `/actuator/prometheus` Output (Simplified)

```
# HELP jvm_memory_used_bytes
# TYPE jvm_memory_used_bytes gauge
jvm_memory_used_bytes{area="heap",id="G1 Eden Space"} 1.2E8

# HELP http_server_requests_seconds
http_server_requests_seconds_count{method="GET",status="200",uri="/orders"} 2543
```

---

## Custom Metrics (Optional but Common)

You can easily add:

```java
@Timed(value = "order.processing.time")
public void processOrder() { }
```

Or counters:

```java
Counter.builder("orders.created")
       .register(meterRegistry)
       .increment();
```

---

## Summary (One-Glance)

**Out of the box, `/actuator/prometheus` exposes:**

* JVM (memory, GC, threads)
* CPU & process
* HTTP request metrics
* Embedded server metrics
* Logging stats
* DB connection pool metrics
* Cache metrics (if present)

👉 Enough to monitor **health, performance, and scalability** without writing any code.
