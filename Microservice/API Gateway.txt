### **2. What Is an API Gateway? (2:52–5:10)**

* An **API Gateway** is a *central point of entry* between clients and backend services in a distributed system. ([GeeksforGeeks][3])

* It acts like a **reverse proxy** — receiving requests from clients and forwarding them to appropriate services. ([GeeksforGeeks][3])

* **Core responsibilities:**

  * **Routing:** Directs requests to the correct backend service.
  * **Authentication & Authorization:** Ensures requesters are allowed to access APIs.
  * **Rate Limiting / Throttling:** Limits how often a client can make requests in a given period.
  * **Security Controls:** Helps enforce API security policies (e.g., token validation). ([GeeksforGeeks][4])

---

### **3. Why API Gateways Matter in Distributed Systems**

* API gateways help **simplify interactions** when there are many microservices rather than one monolith.

  * Without a gateway, clients would need to call each microservice directly.
  * With one gateway, clients only need to interact with one endpoint. ([GeeksforGeeks][5])

* They also **abstract complexity** from clients — handling tasks like protocol translation, request aggregation, and even caching. ([System Design School][6])

### **4. Common Use-Cases & Examples (from system design interview perspective)**

> *Note: specific timestamps or diagrams might be in the video itself. The summary below structures typical interview content.*

#### **Routing and Aggregation**

* API gateway can take a single client request and internally call multiple services.
* It gathers data from different services and returns one combined response. ([System Design School][6])

#### **Authentication**

* Validates tokens (like JWT, OAuth).
* Ensures only authorized clients can access protected services. ([GeeksforGeeks][4])

#### **Rate Limiting & Security**

* Protects backend from abuse by limiting calls.
* Can integrate with firewalls or security checks. ([GeeksforGeeks][4])

#### **Caching**

* Frequently accessed resources can be cached at the gateway layer for performance.

  * Ability to **justify design choices** like adding or skipping a gateway. ([LinkedIn][2])

---

### **6. Pros & Trade-offs of Using API Gateways**

#### **Pros**

* Central point to handle cross-cutting concerns (security, monitoring).
* Simplifies client implementation.
* Helps evolve backend services independently.

#### **Trade-offs**

* **Single point of failure** — if not architected for high availability.
* **Latency overhead** — adds one more network hop.
* **Complexity** — adds another layer to manage. ([System Design School][6])
